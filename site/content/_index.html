New · Expert scoping

An expert asks before the agents spend.

A one-line topic hides a dozen decisions. With --refine, a scoping expert reads your request, asks the few questions that would change the research, and rewrites it into a brief. Nothing runs until you say this is the topic.

  1. Questions written for your topicThree to five, each with real options: the segments, regions and readings that subject actually has.
  2. A brief you can read in ten secondsThe refined topic, what is in scope, what is left out, and the assumptions made for anything you skipped.
  3. You confirm, edit or keep your originalThe planner then follows your answers. The interview is saved with the run as scope.json.
$ boku report "EV charging market" --refine

Dynamic templates

The design follows the subject.

The editor picks a theme that fits what it wrote, or you set one with --theme. Each theme carries its own cover, palette and chart colours through the report and the deck. Sections, tiles and exhibits are chosen per report, not poured into a fixed outline.

Why trust it

Evidence first, prose second.

The model writes; code decides what may be published.

Claims keep their sources

Researchers return structured findings. The editor can cite only findings that survived fact-checking; citations are resolved by code.

Charts and metrics that trace

Column, stacked, bar, line, area and donut charts and headline tiles are drawn only if every value appears in the cited evidence.

A critic with a veto

An independent fact-checker rejects unsupported claims and orders follow-up research. What it cannot verify is printed in a red Not verified box.

Freshness is computed

Every finding carries the date it describes. Boku labels it current or historical against your window; the model never decides.

Shaped by your question

A comparison opens with its matrix, a decision with the recommendation, a one-pager stays one page. Headings follow the request.

Inspectable and resumable

Every artifact lands in a run directory. Interrupted runs resume where they stopped; re-rendering a new format or theme costs nothing.

Modes

One command. Six ways to run it.

No flag gives you the full report. Add one when you want a deck, something faster or cheaper, a whitepaper in research-paper form, or an explainer of a topic or a codebase.

Full report

The default. Built for decisions that need evidence.

  • Planner chooses 1–6 research roles
  • Fact-checker rejects claims, orders follow-ups
  • Cover, contents, charts, diagrams, methodology
$ boku report "How are banks deploying GenAI?"

Slides new

A PowerPoint deck written for the room.

  • Every section has a one-sentence headline
  • Native charts, diagrams and tables
  • Full cited text in the speaker notes
$ boku slides "State of EV charging in Europe"

Short search report

A cited brief when you need the answer, not a book.

  • 3 workstreams, quick depth
  • One fact-check round, no follow-ups
  • Compact layout: no cover, sections flow
$ boku report "Is Postgres 18 AIO worth it?" --short

Quick, on your machine

Every agent runs on a local Ollama model. Zero Claude tokens.

  • Boku searches and fetches pages itself
  • Models may only cite pages Boku fetched
  • No fact-check: treat it as a first pass
$ boku report "GPU sharing on Kubernetes" --quick

Explainer

Understand how a topic, or your codebase, works.

  • Big picture, key ideas, glossary
  • Architecture and step-by-step process diagrams
  • Given a directory, agents read the repo and cite files
$ boku explain ./my-service "auth flow"

Whitepaper

The most detailed format, laid out like a conference paper.

  • Abstract, keywords, numbered sections
  • Captioned figures and tables, [n] citations
  • Deep research; results carry their conditions
$ boku whitepaper "Sparse attention for long context"

Bring your own model

Claude Code by default. Anything else with a config file.

Point Boku at Ollama or any OpenAI-compatible endpoint: vLLM, LM Studio, llama.cpp, OpenRouter. Nothing changes unless you pass a config.

  • Boku's own web search (DuckDuckGo or SearXNG) for models without web tools
  • Sources are re-grounded: a model cannot invent a URL
  • Per-token prices in config give you cost tracking and --max-cost
  • A local model fixes style problems so the main model isn't called again
config.yamlboku report "…" --config config.yaml
agents:
  provider: openai            # claude-code | ollama | openai
  endpoint: http://localhost:8000/v1
  model: Qwen/Qwen2.5-72B-Instruct
  api_key_env: OPENROUTER_API_KEY
  price_input_per_mtok: 0.35
  price_output_per_mtok: 0.40

local:                       # small model for --quick and formatting
  model: llama3.1:8b

search:
  engine: duckduckgo          # or searxng
  max_pages: 12
From one command

Seven stages. Every artifact on disk.

Plan, research, fact-check, synthesis, editorial, quality gates, render. Each stage writes its output to the run directory before the next begins, so you can inspect anything and resume anywhere.
